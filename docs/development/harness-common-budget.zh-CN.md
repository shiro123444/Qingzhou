# 共同预算与经验命令：D 的首个实现增量

2026-10-22。对应[设计 D](harness-next-architecture.zh-CN.md#d-共同预算与经验命令接入-agentsignal--ppt)，接续[受管技能增量 C](harness-managed-skills.zh-CN.md)。本次接入共同预算、付费尝试身份和领域经验命令，保留现有 Chat、AgentSignal 与 PPT 执行流程。真实质量验收、自动付费实验策略及完整恢复调度仍未完成。

## Cordis 服务与领域职责

原生 Profile 在已有 improvement 服务体系中提供 `qingzhou.improvement.budgets` 和 `qingzhou.improvement.experiences`。共同协议放在 [`learning.ts`](../../packages/agent-runtime/src/learning.ts)，服务端预算端口、数据库实现及经验命令放在 [`improvement`](../../src/server/runtime/improvement/production.ts)。领域模块通过这些服务取得预算绑定、生成配置引用和经验记录。

Chat 继续使用 AgentRuntime、匿名比较与独立验证；AgentSignal 保留现有触发器、循环和调度器；PPT 保留 AtomicRuntime、真实渲染适配器、页面边界、原稿保护和产物版本提交。这里没有把三个执行器合成一个，也没有新增自动实验或自动采用。

## 持久父子预算与付费尝试

[`DatabaseLearningBudget`](../../src/server/runtime/improvement/budget-store.ts) 使用按账号和 rootId 寻址的数据库行保存父预算、子分配与尝试回执。分配、预留、结算和取消使用短事务及行锁；模型、网络和渲染工作在事务外进行。相同父身份不能更换主体或额度，相同子身份不能更换分配；所有子额度之和不得超过父额度。每个父预算最多 64 个子预算、256 个尝试。

每次付费尝试在分发前持久预留一个调用及 token、费用额度，记录子预算身份、稳定 attempt ID 和请求摘要。数据库不保存模型密钥、请求正文或可执行句柄。私有请求材料及产物证据继续由领域存储保存。预留落库失败就不分发。

同一 attempt 的相同请求重放返回已存在错误，变更请求返回冲突；此端口不负责重新执行或缓存模型答案。进程在预留后崩溃可能留下 `reserved`，分发后失败则记为 `unknown`；两者均继续占用额度，不因重启或缺少回执自动重发。结算只接受第一次回执，迟到回调不能改写已经结算的状态。

本增量采用保守的**不退还预留**规则，即使已知实际用量更低，也分别保存预留与观测值，不将差额重新开放给后续尝试。领域原有账本可能按自身规则结算；共同账本是总准入约束，二者不能相加当作额外账单。额度和用量回执也不能直接等同于供应商实付费用。

模型返回的用量超过单次预留时，记录观测值并耗尽整个父预算，阻止后续调用和采用。已经发生的供应商超支无法追溯阻止，因此这里保证本地预留准入及超支后的停止，不宣称能强制供应商账单绝不超额。PPT 仅把明确标为 provider-reported 的费用作为费用观测；其他估算继续保留其估算身份。

取消先持久化到父预算，再传播 abort；绑定轮询持久状态，让其他阶段及服务实例也能发现取消或耗尽。外部调用仍可能忽略 abort，现有领域的在途排空和租约继续保留；取消后的迟到值不返回为可用结果，不退还预留。Chat 采用事务还会重新检查该实验关联的父预算，拒绝已取消或耗尽的依据。

子分配逐次原子完成；如果后续子分配失败，之前成功的分配仍被保留，不自动退款。调用者只有取得所需绑定后才开始付费工作。

## 三个领域的接入范围

**Chat**：用户明确启动实验时建立 `chat:<experimentId>` 父预算，以已登记的 probe 和 validation 额度之和为上限，分别分配两个子预算。原方案、候选和匿名选择的每次模型调用均通过绑定预留；独立验证继续使用其登记任务和预算。来源版本、资源 CAS、完整证据和用户确认沿用 B/C 的流程。

**AgentSignal**：学习开关启用时，即时反思、反馈和 review 的既有模型调用进入共同绑定。默认建立 `signal:<sourceId>` 的反思父预算；限制请求大小和输出上限，固定尝试顺序，失败不自动重试。结果通过经验命令保存为待验证观察，失败或取消也留痕；没有结果时配置材料明确标为不完整。

可信服务端宿主也可传入已经分配的 `learningBudget`，让反思、probe、独立验证共享同一个父预算。本次集成测试实际走过这三个执行入口并验证合计准入。**默认 AgentSignal 根和用户手工 Chat 实验根仍分开**，没有新增把所有历史反思自动关联到后续实验的产品策略。用户周期额度配置、自动付费实验调度和崩溃恢复策略仍需后续设计。

**PPT**：生产装配延迟取得共同数据库预算，普通试跑在执行身份下分配一个子预算；两轮串行试跑共享父预算、按轮分配；两页 held-out 验证共享验证父预算、按页面分配。父主体固定为来源演示任务，held-out 页面的经验仍使用各自真实页面任务身份。

当前普通试跑上限为 3 次付费调用、48,000 token、2,000,000 micros；两轮串行上限为 6 次、96,000 token、4,000,000 micros；两页验证合计为 4 次、80,000 token、3,500,000 micros。渲染属于本地工作，不冒充付费模型调用。当前固定真实适配器每个付费操作发送一次模型请求，测试核对实际传输次数；这不代表任意未来插件或供应商的隐式重试已经受控。AgentSignal 和 Chat 的模型初始化同样使用现有单次分发通道。

## 完整经验、真实主体与选择语义

[`LearningCommands`](../../src/server/runtime/improvement/learning-commands.ts) 为完整配置材料生成摘要身份，将领域证据、预算引用、结果、验证状态、适用条件和明确选择关联为 schema v2 经验。配置材料完整保存在私有侧，读取界面只得到必要的经验投影。观察本身不获得采用资格，也不提升为默认能力。

主体使用可辨识联合类型：Agent 的真实 agentId；Presentation 的真实 jobId 和 sessionId。账号仍是租户边界。页面验证可引用同账号来源任务的父预算，因此预算主体与页面经验主体不要求是同一个任务。

Agent 明确采用记录 `behavior-activation`；PPT 用户确认后生成新产物记录 `artifact-fork`。命令拒绝把 Presentation 主体写成行为采用。保留原方案也留下完整配置、证据和选择，不将其伪造为候选质量分数。

Chat 将共同经验随 B 的决定一起原子保存。PPT 使用新的 `protocol-v2` sidecar 保存共同投影；原始领域记录、旧 `protocol` sidecar 和证据身份继续保留，并提供兼容读取。新记录不再以 `presentation:<sessionId>` 冒充 agentId。原稿、已有产物和实际页面提交仍由原领域流程保护。
