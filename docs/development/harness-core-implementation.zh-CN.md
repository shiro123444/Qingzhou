# 核心 Harness 演进：首轮实现与验收边界

2026-10-22 补充：服务端源配置捕获已进入[行为版本与运行快照的第一个增量](harness-behavior-snapshots.zh-CN.md)，提交入口进一步进入[可信写入与原子采用增量](harness-publication-cas.zh-CN.md)。下文保留首轮实现与 2026-10-21 验证的历史范围，当前捕获/采用语义以补充记录为准。

本轮依据[架构设计稿](cordis-harness-evolution.zh-CN.md)推进五个方向。当前可实验和采用的配置面为 `chat.systemRole` 与注册的 `chat.contextStrategy`；受管技能只进入待验证提案。这里的实现范围不等于所有能力已能自动优化。

## 1. 配置快照与运行绑定

公共契约位于 [agent-runtime/harness.ts](../../packages/agent-runtime/src/harness.ts)：规范化数据、SHA-256 版本、账号/Agent 作用域、operation 绑定与完整性校验。凭证字段从配置投影中移除；用户编写的提示和技能正文保留原文。

服务端 [harness.ts](../../src/server/services/agentRuntime/harness.ts) 保存解析后的 Agent 配置、作者原始指令、模型绑定、上下文策略、技能正文、工具目录和 Agent 文档。快照嵌入已有 operation state，绑定也进入 operation metadata 与 trace header。技能列表通过一次批量正文查询补齐；文档在 operation 开始时捕获，执行器优先使用固定副本。

逐步重建 runtime 前重新校验，并从快照恢复配置。当前权限检查、工具执行句柄及步骤状态继续由宿主管理。绑定缺失或损坏时拒绝恢复；存量未绑定任务保留 `legacy/unverified` 标记。材料未能完整读取的运行标记不完整，不允许登记正式实验。

客户端固定完整的已解析客户端配置投影。新运行可向服务器请求兼容的已采用指令，服务器校验账号、Agent、原始指令和模型绑定后才返回最小投影。续跑沿用已有绑定。客户端投影不被当作服务端完整实验的证明。

普通 operation state 仍遵循现有存储生命周期；学习开启后，实验源版本及证据另存于实验存储，不能把普通 Redis state 的存在描述为永久归档。

## 2. 真实执行链中的私有试跑

[HarnessCoordinator](../../src/server/runtime/improvement/coordinator.ts) 与 [Chat probe](../../src/server/runtime/improvement/chat-probe.ts) 复用真正的 AgentRuntime、GeneralChatAgent 和 Cordis plan/execute。上下文使用现有 `serverMessagesEngine` 与 SkillResolver；实际发送的上下文进入私有回执。

私有宿主只安装文本调用与完成操作，不挂载消息数据库写入、生产工具分发、设备操作和 AgentSignal 写入器。额外的执行策略拒绝非文本指令。匿名选择使用独立上下文，不注入候选的 Agent 文档和技能。

第一版只支持纯文本任务；工具、检索、设备及外部写入任务不在本轮实验资格内。并未把 Cordis Context 当作系统沙箱。

实验登记时固定：原版本、候选差分、1–3 个试跑任务、2–3 个未见验证任务，以及两个阶段各自的预算。差分不能修改权限、模型、代码路径或插件目录。查看过独立验证结果的任务不能被新实验复用。

每次调用先持久化预留，再启动模型；调用、输入大小、输出上限、token、费用记账和阶段时限均有边界。未知使用量保留预留，不按零退还；超过回执上限则停止后续调用。费用预留与供应商实测费用分别记录，预留金额不是实际账单证明。没有自动模型重试。

实验初始化显式要求单次分发能力，并关闭 SDK 重试。当前声明支持 OpenAI、DeepSeek、Azure 传输，以及映射到 OpenAI SDK 的自定义供应商；其他传输在调用模型前拒绝试跑，普通对话不受该实验限制影响。上游代理内部的执行仍由供应商负责，不能用本地调用次数证明其账单。

取消和时限传播到模型调用；不接收取消后的迟到结果。在途调用未结束时继续持有实验写锁，避免另一次实验复用额度。固定示例策略与测试模型只能验证这些机制，不能证明真实业务质量提升。

## 3. AgentSignal 的学习写入入口

学习启用后，下列生产路径创建的 SkillManagementDocumentService 带有 `agent-signal` 来源：即时反思、反馈意图、夜间 review、brief 审批和 analyzeIntent 技能管理。

这些路径的创建、替换和重命名会先记录完整提案；替换与重命名同时保留原技能内容。共享资源不立即修改。受限工具将其记为 `proposed` 并产生 receipt，既有置信度门槛不再直接授予新模式中的写入资格。用户主动编辑使用原有文档服务策略。

**未完成的功能边界：** 受管技能文档与全局技能集合是不同的数据模型。本轮没有伪造它们的对应关系，也没有提供受管技能的自动实验、采用和跨存储提交。提案保持 `pending-validation`；必须补齐该领域的 surface、代表任务与资源 CAS 后才能启用。

即时反思与夜间 review 的原有 AgentRuntime 现在可读取固定源指令，并通过 `proposeHarnessInstruction` 提交完整指令候选、理由和当前可见依据。提案端口不提供实验分数、独立验证任务、模型调用或采用权限；同源同内容提案幂等保存。设置界面可载入并检查候选，再由用户登记代表任务和固定预算。

指令配置的提案、比较、独立验证、明确选择和采用已有完整入口。当前不自动登记或执行付费实验；AgentSignal 的现有反思模型预算与用户明确授权的实验预算仍分属两个调用流程。自动化调度需要先为两者提供统一父预算，不能在本轮偷偷追加模型调用。

## 4. 独立验证、采用与回滚

匿名选择种子化输出顺序，支持平局和未知；平局保留原方案，评价格式失败不视为质量零分。验证阶段没有修改候选或生成提案的步骤。

候选必须在试跑与登记的独立任务中均胜出，才能由账号所有者明确确认。采用校验候选 ID、原始配置和活动版本 CAS；活动指针与决定记录在同一原子文件发布中保存。所有旧版本与证据保留。用户编辑导致原配置变化时，新运行停止使用旧候选，并留存回退记录。缺失的用户选择理由保持未知；公共经验也关联本次明确选择，区别于模型评价结果。

回滚恢复原配置，新运行读取新的指针，旧运行继续使用自己的绑定。配置回滚不撤销已发生的外部动作。

[认证 tRPC 入口](../../src/server/routers/lambda/agentHarness.ts) 已注册到主路由。[设置界面](../../src/features/AgentSetting/AgentSelfIteration/HarnessExperiments.tsx) 位于既有自我迭代设置下，提供登记、试跑、独立验证、查看回答和理由、保留、明确确认采用、取消与回滚。

界面固定示例额度为试跑 3 次、验证 6 次调用，每次最多输出 512 tokens；两个阶段分别限时两分钟。后端再次校验额度，不依赖前端按钮状态授权。

## 5. PPT 协议兼容与技术扩展

[captureLearningEpisode](../../src/server/runtime/improvement/episode.ts) 为领域档案生成共同经验投影与不可变配置版本。PPT 通过独立 sidecar 保存该投影，原 episode ID、原稿、档案摘要、选择和验证记录不变。旧档案可以按需投影；没有配置证据的失败尝试不会被补成虚假完整版本。公共选择记录指向实际被选中的配置、请求身份、原版本和产物新版本，并区分 `artifact` 与 `harness`：采用单页产物不会被提升为全局 Agent 能力。

PPT 的领域预算、渲染与评价器继续由现有实现承担。本轮没有把它们重写成 Chat 的执行流程，也尚未统一两个领域的存储后端与全部协调步骤。

[上下文策略服务](../../src/server/runtime/improvement/context-strategy.ts) 是第二种接入实例：原生 Cordis 挂载 `qingzhou.context.instructions`，普通服务端执行与私有试跑均消费该服务，再进入现有上下文管线。默认策略保持原行为；`evidence-first` 提供另一种注册实现。两个配置版本分别通过真实上下文管线和同一预算端口试跑，匿名评价不消费任一候选的上下文。策略通过相同独立验证与采用入口生效；候选不能引用任意代码路径。设置界面从服务端注册元数据取得选项，后续扩展同一服务时无需在 PPT 和 Chat UI 中增加策略分支。

## 启用与部署范围

- `QINGZHOU_HARNESS_LEARNING_ENABLED=1`：启用新实验和 AgentSignal 学习写入门槛；同时遵循用户 feature flag 与 Agent 自我迭代设置。关闭学习不会撤销已明确采用且仍兼容的配置；取消和回滚仍由账号所有者控制。
- `QINGZHOU_HARNESS_DATA_ROOT`：私有实验目录，默认当前进程目录下的 `.data/harness`。生产应显式配置持久卷，避免启动目录变化影响读取，并遵循账号数据保留与删除要求。
- `QINGZHOU_CONTEXT_STRATEGY`：可信宿主为新服务端运行选择的注册策略，默认 `standard`。策略进入版本快照；旧运行不跟随环境变量变化。

本轮未修改实际部署环境或默认开启实验。界面需要先有一次服务端运行捕获完整原配置，才能登记实验。默认上下文策略不会改变现有回答。

当前实验存储适用于单宿主及共享同一文件系统的本地进程，使用排他写锁与原子 rename。账号/Agent 范围最多保存 32 个实验、128 个配置版本、128 个待验证技能提案、128 个指令建议和 16 MiB 状态。达到容量后拒绝新增实验数据，不删除原证据；普通新请求可使用原配置继续。

协调器依赖 `HarnessStore` 契约，文件存储只是当前提供者。契约要求作用域租约、可持久化的中间检查点和独立取消；后续数据库实现不应在模型调用期间保持长事务。

崩溃遗留锁需要管理员核查后恢复，不能自动抢占。它不等于跨多副本的分布式预算、持久化工作流恢复、长期账号配额或完整删除任务。扩大部署前应将该存储契约迁入具备事务与可靠租约的后端。

## 验证方式与剩余工作

定向验证覆盖：规范化版本、正文变化、并发配置编辑、两条 metadata 通道、旧任务恢复、跨账号读取、差分越界、原方案保留、候选胜出、独立验证、取消后的迟到结果、费用超限、重复运行、采用 CAS、回滚、认证接口与客户端最小投影。

还应持续执行既有 RuntimeExecutors、客户端 streamingExecutor、AgentSignal 资源工具、技能文档和 PPT 代表页/独立验证回归。测试使用确定性模型驱动及实际 Cordis、运行器、上下文管线和临时文件存储；不代表真实供应商业务收益或浏览器端到端验收。

后续仍需完成：受管技能的领域实验与采用；自动付费实验的统一父预算与调度；PPT 协调与存储的进一步迁移；真实账号、模型及浏览器验收；多副本与账号保留/删除流程。完成这些后，才能按设计稿的完整标准宣布五步全部完成。
