# 可信写入、资源 CAS 与原子采用：第二个实现增量

2026-10-22。对应[下一阶段设计 B](harness-next-architecture.zh-CN.md#b-收敛采用授权与持久化提交)，接续[行为版本与运行快照](harness-behavior-snapshots.zh-CN.md)。本记录限定本次已实现的提交边界，不代表 C–E 已完成。

## 行为变化

现有 `chat.systemRole`、注册的 `chat.contextStrategy` 的采用入口改为数据库短事务。实验执行和预算流程继续使用原有提供者；普通新运行从数据库读取采用结果，不等待实验作用域的长写锁。

采用事务将活动指针、完整采用依据、用户决定、共同经验投影和待投递事件一起提交。失败时全部回滚，避免指针生效而决定或证据丢失。原始作者配置不被候选覆盖；旧运行继续读取已固定的行为版本与运行快照。

“保留原方案”明确选择对比中展示的源配置，并清除此前的活动候选。它不会继续使用未在本次比较中展示的旧候选。历次决定和完整证据仍保留。回滚也产生新发布代数，停止对新运行应用活动候选，不撤销外部动作。

## 可信写入授权

[`MutationAuthority`](../../src/server/runtime/improvement/mutation-authority.ts) 由可信服务端入口签发，以内存对象身份校验，不能从 JSON 或工具参数反序列化。它绑定账号并区分明确用户编辑与自动学习；自动学习身份不具备发布资格。

[`SkillManagementDocumentService`](../../src/server/services/skillManagement/SkillManagementDocumentService.ts) 的创建、替换、重命名要求该授权；缺失、伪造、跨账号授权均拒绝。即时反思、反馈、夜间 review、brief、analyzeIntent 和隐藏的技能工具入口均显式归类为自动学习。

学习开关开启时，这些自动写入继续暂存完整提案，不修改共享技能正文。开关关闭时，已归类的自动入口保留原有兼容行为；不能据此宣称全系统已禁止所有自动写入。普通文档/VFS 和账号级技能编辑仍由各自认证服务负责，本次没有把所有编辑器迁入同一新命令接口。

## 资源版本与提交校验

迁移 [`0110_harness_publications.sql`](../../packages/database/migrations/0110_harness_publications.sql) 为 Agent、文档、文档绑定、账号技能增加数据库维护的 `generation`。语义字段变化才推进代数；单纯修改访问/更新时间不推进代数，调用者也不能把代数改回去。正文改动后再恢复原文和时间戳，仍会被识别为新资源版本。

受管技能替换/重命名在渲染前捕获文档和绑定代数；渲染在事务外完成。短事务内锁定所属 Agent，重新检查资源归属、可写权限、删除状态及代数，再尝试保存既有编辑器历史，并一起提交 bundle 元数据、索引正文和加载策略。成功写入的历史也随事务回滚；缺少有效编辑器数据的旧文档仍沿用历史跳过规则，不把它当作完整技能版本仓库。创建/转换也重新检查源资源和名称冲突。这里补齐的是资源写入 CAS，尚未开放受管技能候选的实验采用。

[`DatabaseHarnessPublication`](../../src/server/runtime/improvement/publication-store.ts) 的采用命令检查：

- 用户实际看到的活动代数/活动 ID、源版本/源代数和完整验证清单摘要。
- 候选与原始差分、试跑及验证清单的对应关系；候选必须完成既有独立验证资格。
- 当前账号授权、Agent 学习策略、数据库源资源和持久取消标记。
- 幂等请求身份及完整命令摘要。

采用使用 SERIALIZABLE 事务及锁等待/语句超时；完整源配置由普通运行与提交校验共享的技能解析逻辑重新构建。事务内不调用模型、渲染产物或发送通知。冲突返回 stale/CAS，要求刷新并重新明确选择，不重跑推理。源资源在提交后继续变化时，下一次新运行因源版本不匹配而使用新源配置。

同一命令重放返回原决定，即使实验文件已删除、源配置后来变化或学习开关已关闭；不同命令不能占用同一幂等身份。旧 schema 证据仍可查看，但缺少完整 v2 来源的旧候选需重新捕获、验证和确认，不自动迁移为新发布。

## Cordis 服务、运行绑定与取消

提供者实现 [`HarnessPublicationPort`](../../src/server/runtime/improvement/publication.ts)，由原生 Cordis 服务 `qingzhou.improvement.publications` 装配。事务协议与数据库实现分开，后续提供者可在同一服务契约下替换。

发布成功的新运行在受摘要保护的运行快照中记录 `decisionId` 与发布代数。临时模型/provider 不兼容时，使用源行为且不绑定该采用决定；后续默认模型运行仍可读取适用候选。续跑不重新查询最新活动指针。

设置界面发送用户已查看的源/活动代数和验证摘要。并发冲突会刷新比较结果并等待新的明确确认，不自动重试采用；源已过期或实验已取消时禁用不适用操作。

取消保留原文件取消/abort 流程，另在数据库记录取消标记，并与采用串行化。数据库取消先提交时，已准备但未提交的采用依据也会被拒绝；采用已提交后，取消不追溯撤销该决定。文件取消与数据库标记不是一个分布式原子事务；这一步没有重写实验执行租约。

## 提交后事件与经验保存

完整的原/候选配置、差分、实验清单和验证依据保存在决定的私有 JSONB 中；查询接口只返回决定、经验投影和受限展示数据，不返回整个私有依据。用户选择和独立验证分别保存，保留原方案同样产生经验；没有编造未填写的选择原因。

事务 outbox 通过 Cordis `qingzhou.improvement.published` 在提交后投递。确认及幂等重放会尝试刷新待投递事件，也提供独立的 `flushOutbox` 恢复端口。投递失败不会撤销采用，也不重复执行模型。数据库时间控制租约，fencing token 防止迟到投递者覆盖新投递者的回执。

事件为至少一次语义：接收者需按账号/主体/事件身份去重，按发布代数处理失效通知或重新读取最新 head，不能把旧事件直接当作最新指针。当前普通运行直接读数据库，不依赖该通知维持活动缓存。

本增量没有新增持久 outbox 调度器；进程在提交后崩溃且没有后续重放时，仍需恢复调用/调度器触发投递。完整依据暂以内联 JSONB 保存，尚无私有材料 blob 去重与保留任务。数据库账号/Agent 删除会级联清理新表；文件实验档案的统一账号清理仍待后续实现。

使用真实 PGlite SQL 迁移和事务验证发布、代数、故障回滚、权限变化、ABA、幂等重放、取消、outbox 重试/迟到回执；界面组件验证查看令牌和冲突后再次确认。PGlite 测试不代替生产 PostgreSQL 多连接、多进程故障验收。

回归还覆盖普通聊天创建/恢复、AgentSignal 技能入口、客户端执行、原有实验预算/取消，以及 PPT 原稿保护和实际 PNG 渲染。模型回答及胜负由确定性测试驱动；没有调用付费模型，也没有完成真实账号浏览器端到端验收。

最终定向回归为 34 个文件、511 项测试全部通过；数据库 Agent、账号技能及文档模型另有 3 个文件、161 项测试通过。生产修改文件通过定向 ESLint，相关源码/测试/本地化/记录通过 Prettier 检查，`git diff --check` 通过。

已执行全仓 `bun run type-check`，改造前后诊断逐项一致：仍有 6 处既有问题，分别是 `fetch-sse/parseError.ts` 两处 i18n 参数类型、Presentation 文档工具三处缺失 `pdf-lib` 及关联类型诊断、`store/runtime/index.test.ts` 一处 RuntimeClient 可选方法类型不匹配。本轮没有新增类型诊断，但不能声明全仓类型检查通过。
