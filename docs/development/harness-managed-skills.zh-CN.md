# 受管纯文本技能：第三个实现增量

2026-10-22。对应[设计 C](harness-next-architecture.zh-CN.md#c-打通一个受管技能的真实使用闭环)，接续[原子采用与资源 CAS](harness-publication-cas.zh-CN.md)。本次打通服务端技能材料、私有试跑和明确采用的产品链路；真实业务质量仍需账号、模型与登记任务验收。

## 范围与原方案保留

新增 `managed.skillBody` 编辑面，只替换已有受管 `SKILL.md` 的正文。名称、描述、原始 frontmatter、文档/绑定身份、资源关系和加载策略均保留。候选不能创建或重命名技能、修改脚本/附属资源、打开禁用技能，或声明新的执行权限。

首个资格集合要求：同账号及 Agent 的可读、可列举、可写索引和 bundle；已明确允许渐进加载；bundle 只有一个规范索引且无附属文档；frontmatter 只有名称与描述；使用默认文本位置/格式和无条件规则。自定义 token 限制、加载位置或其他策略不被悄悄扩大，暂不进入该集合。禁用、条件加载、复杂资源及格式异常的技能继续由原文档系统处理。

采用发布不可变的技能正文覆盖，只改变该 Agent 新服务端运行所选择的行为版本，不改写作者文档。资源 CAS 校验原文档和 bundle 的代数、权限与归属；完整原文、候选及依据随采用决定保存在 B 的事务中。这样保留原稿，也避免为了让候选生效而反向修改源版本。

“保留展示的原方案”选择实验原配置；回滚停止对新运行应用候选。它们均不改写已经开始的运行，也不撤销外部动作。每轮只比较一个声明的差分，不把先后独立胜出的技能候选未经联合验证地组合起来。

## 来源、加载和固定版本

[`SkillRevisionRef`](../../packages/types/src/skill/index.ts) 记录来源、账号/Agent、bundle/索引资源 ID 和绑定 ID、各自代数、正文摘要及材料版本 ID。受管技能使用独立的 `managed-skill:<bindingId>` 身份；它不冒充内置或账号级技能。现有内置/账号技能读取路径保留。

[`resolveManagedSkills`](../../src/server/services/agentRuntime/managedSkills.ts) 从已捕获的 Agent 文档解析材料，并经普通运行与发布检查共享的 [`resolveOperationSkills`](../../src/server/services/agentRuntime/skills.ts) 进入现有 SkillEngine / SkillResolver。文档快照与技能解析使用同一份已捕获文档，避免两次读取拼接出不同材料。符合资格的索引通过技能管线提供，运行投影排除其重复文档入口，原始文档仍完整留在行为证据中。

目录可见与正文激活分开。渐进技能不会因为名称出现在插件集合里就自动加载；需要显式技能激活。普通运行和续跑都读取已固定的正文，步骤激活带回的其他正文不能覆盖该版本。两条现有服务端技能激活入口均传递 operation 的固定材料；技能命名空间内的缺失版本明确失败，不回退到最新文档或同名账号技能。

权限不随正文快照永久冻结。动态激活及每次后续模型调用使用正文前，重新检查当前文档归属、读取权限、删除状态和加载策略。禁用、撤权或丢失资源会阻止后续使用；单纯编辑正文不会把新正文偷换进旧运行。已经发送的上下文或已发生的外部操作无法追溯收回。

文本激活按需创建文件/资源服务，因此不要求预先配置 S3。只有后续确实请求文件、附属资源或脚本时才进入原有相关服务；此改动不为文本试跑挂载那些执行能力。

## 私有试跑与评价边界

登记时固定目标绑定、原配置、正文差分、试跑任务、未见任务和两阶段预算。试跑和验证对原方案、候选显式加载同一技能，这是渐进技能实验相对普通运行的一项声明差异；普通运行仍需要自己激活。两者通过现有 AgentRuntime / Cordis 执行及实际上下文编译，使用相同的固定技能材料。

[`createChatProbePort`](../../src/server/runtime/improvement/chat-probe.ts) 将候选正文送入实际模型请求；匿名选择只接收任务和匿名回答，不接收技能正文、身份或作者指令。纯文本探针不挂载工具、脚本、文档写入器或 AgentSignal 自动写入器。

沿用既有预算预留、输入字节限制、输出上限、时限和取消机制。编译后的上下文超出输入限额时，在模型发送前失败；已预留费用不据此假装为供应商实际账单。取消后不采纳迟到结果，在途请求排空前仍保留实验租约，不自动重发付费调用。

验证失败或评价未知不获得采用资格。保留原方案仍保存完整候选和证据，不把保留视为候选失败分数，更不把单次选择提升为默认通用能力。现有 AgentSignal 技能学习意图继续待验证，本轮没有自动把历史意图转换为新的付费实验。

## 界面、明确选择与提交

既有自我迭代设置增加受管技能正文选项、符合资格的目标列表、原正文和候选正文。实验详情保留该实验自己的原正文，不用后来更新的正文替代比较依据。页面说明采用范围为服务端行为版本。

认证接口将目标绑定固定在差分里。采用继续携带用户实际查看的源版本/代数、活动代数及验证摘要；B 的短事务重建当前源，并对具体 bundle/索引执行资源 CAS，然后原子保存发布指针、决定、完整证据、经验投影和 outbox。并发变化要求刷新并重新确认，不自动覆盖或重试模型。

客户端现有接口只能投影作者指令，不能完整传递固定技能材料。它遇到技能采用时返回无适用投影，不标记为技能已应用；客户端技能材料接入仍是明确的后续边界。内置/账号技能的脚本、资源与完整动态激活版本固定也未在本增量扩展。

## 验证边界

定向测试使用真实 PGlite 数据库、迁移、文档服务、源解析、实际 probe 上下文编译、发布事务、技能工具工厂和 UI 组件。覆盖候选胜出、原方案胜出、独立验证失败、未知评价、正文与绑定 ABA/权限/策略冲突、取消、输入预算、旧运行固定正文，以及撤权后阻止后续模型调用。

模型传输由确定性测试回调提供；实际请求中原/候选正文、匿名评价隔离和调用数量均有断言。这些证据证明机制及适配链路，不证明真实模型质量提升。未调用付费模型、未部署数据库迁移或开关，也未完成真实浏览器/多进程 PostgreSQL 端到端验收。

最终回归：应用层 23 个文件、342 项测试通过；上下文引擎 3 个文件、20 项测试通过，合计 26 个文件、362 项。生产修改文件通过定向 ESLint，相关源码、测试、本地化和记录通过 Prettier 检查，文档链接及 `git diff --check` 通过。

全仓 `bun run type-check` 仍有 6 处既有诊断，与 B 改造前基线逐项相同：`fetch-sse/parseError.ts` 两处 i18n 参数类型、Presentation 文档工具三处缺失 `pdf-lib` 及关联类型诊断、`store/runtime/index.test.ts` 一处 RuntimeClient 可选方法类型不匹配。本轮未新增诊断，不将此结果描述为全仓类型检查通过。
