# 清舟 PPT 工作台的画布、模板与原生数据

本次考察基于本机 ppt-master 的 `3af3e8ef`，即 v6.9.0 之后第八个提交。清舟沿用它的设计资产和 PowerPoint 转换器。页面的事实、数据、手动改动、生成版本及发布权限由清舟持有。两端在已确定的 SVG、结构化对象和导出文件上交接。[上游技术设计](https://github.com/hugohe3/ppt-master/blob/3af3e8ef774c4d67ee57e1306d9256d08c9ee1bf/docs/technical-design.md)

## 上游设计中值得保留的做法，以及接入代价

| 关注点 | ppt-master 的强项 | 应用于清舟时需要解决的问题 | 清舟的处理 |
| --- | --- | --- | --- |
| 模板 | Brand 管身份，Style 管表达，Layout 管槽位，Deck 管一整套演示；不同资产有明确的控制范围 | 将所有来源揉进一个提示词会遗失来源、可容纳的内容和冲突优先级 | 导入风格方法与布局槽位，记录来源摘要、观察页、能力 ID 和实际编译回执。整稿身份与页脚由统一的设计规范生成。品牌、整套 Deck 和用户导入模板的路径需要分别评估覆盖范围 |
| 分镜与排版 | 先锁定工作规格，再按页面角色和选定材料设计 | 选中一个模板只说明它可检索。槽位可能容不下实测公式、原图或表格 | 分镜阶段先检查角色与槽位兼容性。编译时按字体、表格行高、公式和图像实测。单图表也能使用学得的对象槽，表格优先专用表格槽，缺少专用槽时再测算通用对象槽。回执给出所用布局或跳过原因；修复沿用同样的编译条件 |
| 内容与素材 | 按来源分别处理资料、图片、设计材料；规范约束图片在页面中的角色 | 一张预览图难以表达原始数据、出处和哪些对象允许重绘 | 保留原图引用、公式源、表格网格、显式采样点和备注。分镜将“如何混排”与“是否需要新图”分别记录，老任务可从检查点恢复。页面修改从账户有权使用的资料派生；数据编辑只提交精确的变化 |
| 作者与运行时 | 分工清晰，文件及中间 SVG 容易人工检查，适合本机开发；原生往返有专用流程 | 工作目录、会话上下文和单项目编辑服务器本身不能解决多账户所有权、跨任务调度与重复付费 | Cordis 挂载和租用能力，任务协调器拥有版本写入权，分镜、素材、页和审核有交接记录。模型按角色调用，已知坐标与数值改动直接执行 |
| 可编辑交付 | 支持的文本、矢量及原生数据可映射到 DrawingML，图表有配套工作簿，原稿往返能保留特定未修改部件 | 预览正确与下载文件可改是两件需要分别实测的事。SVG 与 Office 图表的字体、图例位置、轴标签受查看器影响 | 页面数据同时驱动预览和上游原生数据描述。交付前读取 PPTX 中的表格、图表引用、数据缓存和嵌入工作簿并逐项核对 |
| 人工编辑 | 上游自带项目级网页 SVG 编辑器，支持标注、编辑、撤销、暂存和保存 | 直接嵌入还需同步项目路径、登录、活跃版本、可见工件以及清舟的任务状态 | 工作台内选择对象、预览位置、显式应用并进入原有版本链。保留完整页面的原 SVG、旧版本与下载入口 |
| 审核与发布 | 输入规则、SVG 质量门及转换后检查给出清晰的失败位置 | 上游单视图的质量结果不能解释多用户版本冲突、同行页是否被重写、审美接受度 | 并用内容/几何检查、整稿视觉审核、结构验证。单页修改限制可修复页面；整稿仍要通过才能发布。纸面协议、实际软件打开和人工视觉判断分别记录 |

## 四种画布的取舍

| 方案 | 本产品实际用得到什么 | 接入影响 |
| --- | --- | --- |
| Konva，MIT | 分层、指针命中、拖动和选择反馈。按需加载，能覆盖在原文档上 | 已采用。保留既有 SVG、字体度量和语义对象；交互坐标按页面单位计算。[官方文档](https://konvajs.org/docs/) |
| Fabric.js，MIT | 完整的可编辑图形对象和 SVG 导入导出 | 对以 Fabric 为源的编辑器合适。把现有幻灯片整体转换为 Fabric 对象，需要重新核验字体、SVG 标签和结构化对象的往返保真。[核心概念](https://www.fabricjs.com/docs/core-concepts/) |
| Excalidraw，MIT | 自带白板界面、开放场景格式、图形和协作生态 | 自由绘图较完整。清舟已有模板版式、讲稿和原生对象，独立的白板场景会增加一次双向映射。[项目说明](https://github.com/excalidraw/excalidraw) |
| tldraw SDK | 提供成熟的无限画布、形状和工具扩展机制 | 生产部署有许可要求。当前需求由轻量交互层和现有文档模型覆盖。[官方许可说明](https://tldraw.dev/faq) |

工作台参考 WorkBuddy 将任务、对话与结果分开的组织方式。页面列表管定位，中央工作区管设计，浮动液态玻璃工具栏管选择、平移、适屏、数据编辑和播放。玻璃效果属于工作台界面，下载的幻灯片按用户选定的模板呈现。[WorkBuddy 产品指南](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Product-Guide)

## 操作与数据如何流动

1. 内容及设计阶段交付带身份的页面、结构化内容块及 SVG。工作台在实际 SVG 上绘制独立命中层。选中、平移和缩放留在浏览器，页面坐标、PPT 数据和资产不受视口操作影响。
2. 通用画布接收边界、对象矩形、目标 ID 和逻辑坐标。PPT 适配器带上所属页面和期望版本向既有账号接口提交。后端对越界、语义块重叠、过期版本及错页对象给出错误。通用 Cordis 操作只接收几何信息。
3. 经确认的移动更新语义块与单对象原生边界，再渲染目标页。数据编辑则更新 XY 系列。原大纲、页内文字和讲稿中能与旧系列精确匹配的对应点列会同步更新；点名了坐标轴的数列以及可复算的一阶差分按新数据重算。人工放置的对象在后续稳定化阶段保留位置。
4. 局部操作记录页级交接。再导出时，优先使用上一完成版本中同一账户的同行页工件，复用原图。视觉审核仍读取整份文稿，最终打包也需要处理整份 PPTX。
5. 对兼容的表格或 XY 图表，只有当可见对象与确定性渲染的结构相符，才会在转换副本上标记原生替换。上游将数值写入 Office 图表及工作簿，清舟反查文件内部的实际内容后发布。图表数据编辑器根据逐页导出回执注明 PowerPoint 的实际图表类型。

| 能力 | 当前的产品边界 |
| --- | --- |
| 页面级操作 | 缩略图、画布视口、播放、标注、对话修订与下载适用于现有页面。老文件按所含语义元数据逐项开放对象工具 |
| 对象级移动 | 有来源矩形的公式和 scientific-diagram 对象，包括表格、关系图和采样图。平面图片内的文字仍属于图片内容 |
| 可编辑数据 | 原生网格表格，以及能忠实映射的显式 XY 单/多系列图表。图表命中适配条件和本次验证的题材需分别陈述。计算轨迹、矢量箭头和等比例科学绘图继续保留其专门表示 |
| 格式覆盖 | 上游还支持更多图表种类、动画、音频及原生文件往返。当前画布适配范围由已实现的对象协议决定。复杂 Office 对象的无损任意编辑、多人同时拖动及所有桌面客户端像素一致性均需要单独实现和验证 |

## 本机验收记录 · 2026-11-18

同一账户上传一张新绘制的模拟响应场原图，生成四页《载荷传感器校准》。首稿已能下载，但单图表和单表格缺少布局编译回执。更新适配器后，使用同一任务、同一内容及原图重新编译。正式对照以四页均具有 v12 应用回执的版本为原稿。

| 检查 | 实际观察 |
| --- | --- |
| 布局来源 | 封面命中标题和副标题槽。单图表和单表格分别命中双栏布局的标题、左栏和右栏。原图与公式页命中标题、对象和说明槽 |
| 正常编辑入口 | 在 Chrome 的专注编辑模式将第 2 页第三个纵值从 16 改为 17。重新打开工作台仍读到 17。修订阶段仅产生一次整稿审核模型调用 |
| 数据一致性 | 图线和可见数列、PPTX 图表缓存、嵌入工作簿以及讲稿均采用 17。讲稿所引相邻增量由 4、4、3、3 更新为 4、5、2、3 |
| 局部修改 | 第 1、3、4 页的预览 SVG、PPT 页面 XML、讲稿和页级交接记录逐项一致。原图摘要一致。两次版本的整稿审核、质量检查和账户下载均成功 |

| 视觉复核 | 最终审核保留两条轻微意见：模拟说明靠近图例会更清楚，第 4 页“读数”一词跨行。两条意见均随修订版本留存 |
