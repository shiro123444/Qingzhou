# 版本化材料提供者：E 的首个实现增量

2026-10-22。对应[设计 E](harness-next-architecture.zh-CN.md#e-验证扩展性与真实产品路径)，接续[共同预算与经验命令](harness-common-budget.zh-CN.md)。本次验证一个实际改变模型输入材料的能力实现：受管技能的完整章节解析器。E 的真实模型质量、账号浏览器流程、文件保留/删除及生产部署拓扑验收仍需继续完成。

## 实际接入的能力

保留 `skills.raw@1.0.0` 的原始文本表示，增加 `skills.sections@1.0.0` 的完整有序章节表示。新实现按 Markdown 标题分段，把所有章节作为带固定格式标识的 JSON 材料交给上下文引擎；frontmatter、前言、章节、围栏代码块、原始换行和全部字符都保留。按序拼接章节内容能还原原文。该实现改变实际技能上下文的表示，不增加模型请求。

作用对象沿用 C 的资格集合：同账号及 Agent、已允许渐进加载的独立受管纯文本技能。只有已激活的固定技能正文进入解析器。内置技能、账号技能及未激活目录保留其现有路径。试跑显式激活符合资格的受管技能，这是与普通运行的一项登记差异；普通运行继续遵循原有激活策略。

新编辑面 `context.skillMaterial` 只接受可信注册表中的提供者版本身份，不能携带脚本、模块路径、任意 manifest 或新的执行权限。源文档与加载设置不变；候选保存为私有行为版本，采用后应用到符合范围的新服务端运行。

## Cordis 契约与实现身份

共享包的 [`SkillMaterialManifest`](../../packages/agent-runtime/src/materialCapability.ts) 声明 contractVersion、implementationVersion、配置 schema、编辑面、副作用、取消、用量和回放能力。首批契约只准入无额外配置的纯文本本地解析，使用合作式取消、本地字节回执和确定性回放声明。注册和修改实现均由可信宿主代码完成，模型不能把普通材料升级为提供者代码。

[`SkillMaterialRegistry`](../../src/server/runtime/improvement/skill-material.ts) 按完整提供者 ID 与实现版本寻址。相同键不能覆盖注册；存储的 manifest 和配置必须与已注册版本完全匹配。不同实现版本可以共存，缺失版本明确报错，不读取一个移动的 latest 别名。

[`contextStrategyComposition`](../../src/server/runtime/improvement/context-strategy.ts) 通过原生 Profile 提供 `qingzhou.context.skill-material` 服务。Profile 取得具体版本租约，在原生 effect 清理中释放；提供者有已挂载租约或尚未排空的材料处理时禁止移除。释放后的句柄不接受新调用，已开始的处理也不会返回可供继续执行的迟到值。

普通运行和 probe 调用同一服务契约，之后继续进入既有 `serverMessagesEngine` / SkillContextProvider。注册新的合格解析实现不要求在 PPT 和 AgentSignal 各新增一套选择策略：PPT 保留产物领域规则，AgentSignal 保留提案/经验职责，共同经验和预算继续使用 D 的服务。

纯函数声明及资格测试不构成恶意宿主代码沙箱。当前接口只向解析器提供技能标识、固定正文和 AbortSignal，不提供数据库、工具或模型执行句柄。新的检索、网络或脚本能力需要相应副作用、分发和用量契约，不能沿用本地零模型调用声明获得执行资格。

## 版本固定与回滚

新捕获的行为版本保存原文解析器的完整 manifest 与配置；候选保存被选择实现的完整身份。它们参与行为摘要和配置经验引用。旧版本缺少该字段时，使用固定的 `skills.raw@1.0.0` 兼容语义。新增字段使新捕获的源摘要发生变化时，既有采用继续受源版本匹配检查约束，需要重新捕获和确认。

运行快照不能覆盖行为版本中的解析器选择。普通执行、probe、续跑都根据固定行为身份取得实现；旧实现不可恢复时明确失败。发布和回滚只改变后续新运行的选择，已经保存的旧绑定仍保留原版本。

当前租约保护本进程已挂载 Profile 及在途材料处理，不是跨进程、跨持久运行的全局引用计数。生产发布必须保留仍被历史运行引用的实现；若主动移除了一个休眠运行所需版本，恢复将失败。完整的分布式插件卸载与实验 fencing 仍在部署拓扑验收范围内。

## 用量、取消及用户确认

每次解析输出本地回执：具体提供者绑定、输入/输出字节数、来源标识与摘要、转换后摘要，以及 `modelCalls: 0`。普通运行将回执放入执行状态；probe 将其放入私有模型回执。正文仍在私有配置和实际上下文证据中保存，不由摘要替代。

本地处理最多 64 份受管材料、262,144 输入字节和 1,048,576 输出字节。解析前、处理循环及返回前检查取消；最终编译请求继续接受原有输入字节、输出 token、时限和共同父子预算约束。提供者本身不消费额外付费调用，原方案、候选和选择器仍分别按既有预算记账。

新设置选项从服务端注册表发现，显示提供者版本、原解析器及采用范围；原有源变化警告、比较结果、保留、采用确认与冲突后重新确认流程保留。当前客户端投影只传作者指令，无法表达新的材料解析；遇到此类采用时返回无适用投影，不把它显示为客户端已应用。

采用继续使用 B 的短事务：重新构建源、验证试跑/未见任务、检查当前授权、取消及父预算，对全部涉及的受管索引和 bundle 进行资源 CAS，再原子保存决定、完整配置、经验和活动代数。并发变化要求重新查看和确认，不自动重复推理。失败、未知和保留原方案均保留完整经验，不自动提升默认能力。

## 验证层级

提供者资格测试覆盖完整原文重建、围栏/CRLF/特殊文本、原文解析兼容、未激活技能保留、manifest/配置拒绝、版本共存与缺失、Profile 租约、排空后移除、取消和字节边界。真实 probe 编译测试检查发送的上下文确实改变，选择器保持中立；普通 Chat 执行入口测试检查当前权限先于解析及本地回执保存。

集成测试使用真实 PGlite 文档服务、配置捕获、认证路由、共同预算、匿名比较、独立验证、采用及回滚。覆盖候选胜出、原方案胜出、验证拒绝、评价未知、源资源变化、原稿保留和旧绑定不变。一次路由实验仍只有 9 次确定性模型传输，材料解析没有增加模型调用。组件测试验证服务端发现、版本、作用范围和原版本展示。

账号删除测试走现有 `UserModel.deleteUser`，确认共同预算表级联删除，并保留另一账号的同名预算根。该证据只覆盖数据库预算记录。文件实验、PPT 私有材料和完整经验档案尚无统一账号保留/清理任务，不能据此宣称所有学习数据已完成删除闭环。

本次浏览器清单中没有已登录的 Qingzhou 页面。尝试打开本机 3210 端口，浏览器返回 `ERR_CONNECTION_RESET`；尚无该端口运行本工作树代码的证据。因此未完成真实账号浏览器流程或真实模型质量验证，也未运行多连接、多进程 PostgreSQL 故障测试。确定性胜负用于验证机制，不证明章节表示优于原文表示。

最终组合验证覆盖 **35 个文件、535 项不同测试，均已有通过记录**。主集合中 34 个文件通过，held-out 预算用例因首次数据库初始化、迁移和真实渲染同计入 5 秒窗口而超时。将两个 PPT 集成文件的数据库初始化移到顶层夹具后，两个文件共 42 项复跑通过，保留原业务断言及超时。先前另一轮并行执行中，一项既有 PPT 并发编辑用例超时；单独用例、整个文件的 12 项及后续单 worker 集合均通过，保留并行稳定性观察。以上是组合回归结果。

最终全仓 `bun run type-check` 仍有与 D 逐项相同的 6 项基线诊断：`fetch-sse/parseError.ts` 两项 i18n 类型、Presentation 文档工具三项缺失 `pdf-lib` 及关联类型、`store/runtime/index.test.ts` 一项 RuntimeClient 可选方法类型。本次未新增诊断。生产修改文件通过定向 ESLint，交付源码、测试、本地化和记录通过 Prettier；文档链接与 `git diff --check` 通过。

## 真实验收步骤

在隔离验收部署执行既有 0110/0111 迁移，运行这份工作树；本次没有新增迁移或切换生产开关。使用明确的测试账号、已有渐进纯文本技能、固定模型和预先登记的三项任务：一项比较任务、两项未见任务。开始前固定质量标准与模型预算，候选构造不读取未见任务结果。

在自我迭代设置选择技能材料解析及具体提供者版本，确认作用范围和原版本。依次完成试跑、独立验证、查看比较、明确采用或保留；检查源资源变化会要求重新确认。真实验证不保证某个实现必然胜出，保留原方案也是合法结果。

对采用后的新运行检查实际上下文、版本绑定及回执，对旧运行检查固定版本；执行回滚并确认后续新运行恢复原解析。另行验证权限撤销、取消、测试账号删除及文件清理流程。真实质量结果、浏览器结果、数据库并发/崩溃结果分别记录，未通过的层级不以其他测试结果替代。
